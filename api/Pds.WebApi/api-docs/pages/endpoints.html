Endpoints

Vinte e cinco rotas. Vinte e uma exigem token de sessão; quatro não — a de entrar, que é onde a sessão nasce, as duas que a ferramenta usa (a que recebe o relato e a que ela lê para saber como se desenhar) e a que abre o acompanhamento para quem relatou.

Corpo de requisição e resposta de cada uma ficam no Swagger, gerado a partir do código.

A mesma chave, ora no corpo, ora na URL

POST /public/reports leva a chave pública no corpo; GET /public/widget-settings leva na URL. Não é descuido, e a diferença não é de segurança: a chave é pública nos dois casos, e está à vista no HTML do site do cliente.

O que o carregador evita é outra coisa — pôr a chave no src do quadro, que ficaria no documento do cliente, no histórico de quem visita e no Referer que sai de lá. Esta chamada sai do nosso próprio documento para a nossa própria API, e essa URL não aparece na página de ninguém. Em troca, a resposta pode ganhar cache no dia em que o volume pedir — coisa que um POST fecharia.

Projeto arquivado esconde a ferramenta

GET /public/widget-settings devolve IsEnabled: false para projeto arquivado, qualquer que seja o valor salvo. Ele já recusa relato novo com 403: deixar o formulário abrir levaria a pessoa a escrever até o fim para ser recusada no envio, e o texto dela se perderia por uma decisão que não é dela.

Uma leitura que é POST, e por quê

POST /public/reports/tracking não cria nada — e não é um GET por duas razões. O token é um segredo, e segredo em query string entra no log de acesso do servidor, no histórico do navegador e no Referer que sai da página; no corpo, não entra em nenhum dos três. É o mesmo cuidado que põe o token no fragmento do link (#t=), que é a parte que o navegador nunca envia a servidor nenhum.

E ela não é leitura pura: grava o evento de visualização com origem public_page. O intervalo entre o relato e a primeira olhada do time mede a reação; a volta de quem relatou mede se a camada pública serve para alguma coisa. Nenhum dos dois é reconstituível depois.

O protocolo identifica, o token abre

A rota exige os dois, e protocolo inexistente e token errado recebem a mesma recusa 404, com a mesma mensagem. O protocolo é curto e falado de propósito — logo adivinhável —, então responder diferente contaria a quem sonda que ele acertou metade. E 404 em vez de 403 pela razão de sempre aqui: confirmar que o relato existe já é informação.

A comparação do token é em tempo constante (ProjectKeyGenerator.Matches): um == comum para no primeiro caractere diferente, e com o protocolo em mãos a diferença de tempo permitiria descobrir o token caractere a caractere.

Onde a lista de endereços é conferida

Nas duas rotas que a ferramenta usa, e por motivos diferentes. Em GET /public/widget-settings a recusa é 403 e faz o quadro nunca aparecer naquela página — é o que evita alguém escrever o relato inteiro para ser recusado no envio. Em POST /public/reports ela é o que de fato impede a gravação: sem a segunda, bastaria falar direto com a rota para a lista não valer nada.

Lista vazia autoriza qualquer endereço, e quem não declara endereço passa. A primeira regra existe porque a leitura contrária apagaria a ferramenta de toda instalação no ar no dia em que a conferência entrou — sem erro em tela nenhuma, porque o quadro que não pode abrir simplesmente não aparece. A segunda, porque recusar o silêncio não ganha nada (quem quer burlar declara um endereço válido, não omite) e custa o relato de teste do painel, que abre o quadro sem página hospedeira.

Isto é grade de proteção, e não muro

O endereço é declarado pela própria página. Como quem o declara é o carregador, que é código nosso, a chave pública copiada para outro site é pega — e é esse o caso comum. Quem chamar a API sem passar pela ferramenta declara o que quiser, ou não declara nada.

O muro é o frame-ancestors montado desta lista, que impede o quadro de sequer abrir fora dela. Ele precisa de um servidor servindo o documento do quadro para montar o cabeçalho por projeto, e o quadro hoje é arquivo estático: chega com o domínio próprio.

Uma consulta que grava, de propósito

GET /projects/{publicId}/reports/{reportPublicId} registra um evento de visualização a cada chamada. O intervalo entre ele e a criação do relato é o tempo que o time levou para ir olhar — metade da pergunta que este trabalho investiga, e um dado que não é reconstituível depois.

A consequência vale para quem for consumir a API: ela não deve ser chamada para adiantar dado que ninguém pediu. Uma tela que abrisse os relatos sozinha inventaria leituras que não aconteceram. A lista não registra nada, e é ela que serve para varrer.

Por que uma rota fica fora do padrão

Vinte e uma rotas exigem token e resolvem a conta pelo uid que vem dentro dele. As duas de /public não podem: quem chega ali é um visitante anônimo do site de um cliente, e a conta ainda não é conhecida. A credencial é a chave pública, que não autentica ninguém — ela apenas diz para qual projeto o relato vai.

Chave ausente, desconhecida, revogada ou secreta recebem a mesma recusa, com a mesma mensagem: responder "esta chave existe, mas foi revogada" contaria a quem tenta que ele acertou metade. Ver Isolamento por conta.

Não existe rota de exclusão de projeto

Arquivar cobre o caso real — parar de aceitar coisa nova sem perder o histórico. Apagar projeto envolve o que fazer com os relatos que apontam para ele, e essa decisão é da etapa em que o relato existir.

O envelope

Toda resposta tem a mesma forma, com sucesso ou sem. O painel lê o resultado num lugar só, em vez de descobrir o formato do erro a cada rota.

{
  "Success": true,
  "Message": "Projeto criado.",
  "Data": { ... },
  "Total": 3
}
CampoQuando aparece
SuccessSempre.
MessageTexto para quem está usando. Nulo quando não há o que dizer.
DataO retorno da rota. Nulo quando falha.
TotalSó em listagem.

Por que PascalCase, se o banco é snake_case

É o oposto de propósito. A fronteira fica visível a olho nu: quem lê account_id sabe que está olhando banco, quem lê AccountId sabe que está olhando contrato.

Por que o "Z" na data importa

As datas são gravadas em UTC, mas voltam do PostgreSQL sem informação de fuso. Sem o "Z", o navegador leria cada uma como horário local e a linha do tempo apareceria deslocada — três horas, no nosso caso.

O 500 não conta o motivo

A resposta é sempre "Erro ao processar a requisição". Mensagem interna vazada em resposta conta ao curioso como o sistema é por dentro; o detalhe vai para o log do servidor.

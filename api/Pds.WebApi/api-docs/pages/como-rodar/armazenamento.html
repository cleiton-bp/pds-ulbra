O armazenamento

O MinIO que guarda os anexos, num balde privado.

Em resumo
  • Opcional: só é preciso para anexar no relato, na resposta e na reabertura.
  • Configure as quatro variáveis, ou nenhuma.
  • Os arquivos vão do navegador direto ao balde, sem passar pela API.
cd api
docker compose up -d minio minio-init

Sobe um MinIO (compatível com a API do S3) só em 127.0.0.1:

container pds-minio volume pds-minio-data porta 127.0.0.1:9000 a API do S3 127.0.0.1:9001 o console, para olhar os arquivos (pds / pdspdspds) balde pds-media privado, criado pelo pds-minio-init, que roda uma vez e sai uploads/ onde o navegador grava antes de a API conferir: vence em 1 dia

Depois, no .env.local:

MEDIA_STORAGE_ENDPOINT=http://localhost:9000
MEDIA_STORAGE_ACCESS_KEY=pds
MEDIA_STORAGE_SECRET_KEY=pdspdspds
MEDIA_STORAGE_BUCKET=pds-media

Com metade delas, a subida cai dizendo qual falta. As outras têm padrão e estão em Variáveis de ambiente.

Os bytes nunca passam pela API

O navegador pede permissão, manda o arquivo ao balde por formulário assinado (com teto de tamanho e tipo) e confirma. Na confirmação, a API lê os primeiros bytes e prende o anexo ao relato. A leitura é por link assinado de validade curta. Detalhes em Imagens e arquivos no relato.

O balde privado e a pasta que vence

O minio-init tira do balde qualquer acesso anônimo: link assinado sobre arquivo público não protegeria nada.

A pasta uploads/ vence em um dia. O arquivo aceito sai de lá na confirmação, que aceita até 1 hora depois do pedido.

Só em 127.0.0.1, e não na rede toda

A senha padrão está no repositório público. Aberto na rede, qualquer um ali mexeria na mídia pelo console.

Com a API no compose

docker compose up -d --build

Endereço, chaves e balde vêm do próprio compose, e o .env.local não vale. A API fala com minio:9000 pela rede interna e assina com localhost:9000, o endereço que o navegador conhece (MEDIA_STORAGE_PUBLIC_ENDPOINT).

Por que dois endereços

A assinatura cobre o host. Assinada com minio, o navegador não resolveria o nome; falando com localhost, a API procuraria o armazenamento no próprio container. Fora do compose os dois são o mesmo.

Sem armazenamento

  • A leitura de mídia da ferramenta e da página de quem relatou responde desligado: o botão não aparece.
  • A tela de Anexos não salva nada: PUT .../media-settings responde 409, e a escolha do projeto fica guardada.
  • Pedir permissão, confirmar e ler os arquivos de um relato com anexo respondem 409, e não uma lista vazia que esconderia o anexo.
Em produção

O armazenamento é o MinIO, na mesma máquina da API. Trocar de provedor é trocar variável, se ele aceitar envio por formulário assinado (POST); o R2 da Cloudflare não aceita. Num provedor novo, a regra de CORS do balde também precisa ser configurada.

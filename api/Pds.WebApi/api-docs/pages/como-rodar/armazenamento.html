O armazenamento

Opcional. Só é necessário para anexar: imagens e arquivos no relato, na resposta ao time e na reabertura. Sem ele, todo o resto funciona, e a tela de Anexos recusa ligar o anexo, dizendo por quê.

cd api
docker compose up -d minio minio-init

Sobe um MinIO — compatível com a API do S3 — só em 127.0.0.1:

container pds-minio volume pds-minio-data porta 127.0.0.1:9000 a API do S3 127.0.0.1:9001 o console, para olhar os arquivos (pds / pdspdspds) balde pds-media privado, criado pelo pds-minio-init, que roda uma vez e sai uploads/ onde o navegador grava antes de a API conferir — vence em 1 dia

Depois, no .env.local:

MEDIA_STORAGE_ENDPOINT=http://localhost:9000
MEDIA_STORAGE_ACCESS_KEY=pds
MEDIA_STORAGE_SECRET_KEY=pdspdspds
MEDIA_STORAGE_BUCKET=pds-media

As quatro, ou nenhuma. Ausentes, a API sobe e o anexo fica desligado; metade delas derruba a subida, dizendo qual falta — não configurar é uma decisão, e esquecer a chave é um engano que ficaria escondido como "mídia indisponível" até alguém passar uma tarde procurando. As demais variáveis do armazenamento têm padrão e estão em Variáveis de ambiente.

Os bytes nunca passam pela API

O navegador pede permissão, manda o arquivo direto ao balde por um formulário assinado — com o teto de tamanho e o tipo dentro da assinatura — e confirma; é na confirmação que a API lê os primeiros bytes e prende o anexo ao relato. A leitura é por link assinado de validade curta, gerado sob demanda, depois de conferir quem pede. A sequência inteira está em Imagens e arquivos no relato.

O balde nasce privado, e a pasta de envio vence

O minio-init cria o balde e tira dele qualquer acesso anônimo. Não é zelo: link assinado sobre arquivo público não protege nada, e um balde que nascesse aberto faria toda a assinatura da aplicação virar enfeite. Repetir o passo é inofensivo.

A pasta uploads/ vence em um dia. O arquivo aceito sai de lá na confirmação, e o que sobra — envio abandonado, reenvio depois de confirmado — não é anexo de ninguém. A confirmação aceita até 1 hora depois do pedido, então um dia não apaga nada que ainda possa entrar.

Só em 127.0.0.1, e não na rede toda

A senha padrão está no repositório, que é público. Publicado em todas as interfaces, qualquer um na mesma rede entraria no console e leria ou apagaria a mídia. A API dentro do compose não passa por essas portas — fala com o armazenamento pela rede interna.

Com a API no compose

docker compose up -d --build

O endereço, as chaves e o balde vêm do próprio compose, das mesmas fontes do minio e do minio-init, e as linhas do .env.local não valem — a variável real tem precedência sobre o arquivo. De dentro da rede a API fala com minio:9000, e assina com localhost:9000, que é o endereço que o navegador conhece (MEDIA_STORAGE_PUBLIC_ENDPOINT).

A assinatura cobre o host

Por isso existem dois endereços. Assinada com o interno, a permissão levaria o navegador a um nome que ele nem resolve; e a API que falasse com localhost de dentro do container procuraria o armazenamento nela mesma. Ela fala com um e assina com o outro — assinar não faz chamada nenhuma. Fora do compose os dois são o mesmo, e a variável do endereço público nem precisa existir.

Sem armazenamento

A API sobe inteira, e o armazenamento responde que não está disponível:

  • a leitura de mídia da ferramenta e da página de quem relatou responde desligado, mesmo com o anexo ligado no projeto — o botão não aparece;
  • a tela de Anexos não salva nada, nem o anexo desligado: PUT .../media-settings responde 409. Gravar o desligado que a leitura mostra apagaria a escolha do projeto, que volta a valer quando houver armazenamento;
  • pedir permissão e confirmar respondem 409, e ler os arquivos de um relato que tem anexo também — dizendo que não há armazenamento, e não com uma lista vazia, que faria o time achar que o relato nunca teve anexo.
Em produção — Adiado

Trocar de provedor é trocar variável, desde que ele aceite envio por formulário assinado (POST) — o R2 da Cloudflare não aceita. Nada no código nomeia o MinIO: a API fala a API do S3 com o endereço e as chaves que vierem do ambiente, e a região e o balde no caminho são configuráveis para o provedor que pedir diferente.

A escolha fica para quando houver hospedagem, junto da regra de CORS do balde: é o navegador, de dentro do quadro, que envia direto ao armazenamento, e o balde precisa deixar essa origem enviar.

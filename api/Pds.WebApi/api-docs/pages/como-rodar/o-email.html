O e-mail

Opcional. A API manda e-mail por SMTP, que todo provedor fala: trocar de provedor é trocar configuração, e não código. Sem a seção Smtp, a API sobe normalmente e o envio responde que não está disponível. Hoje nada no produto manda e-mail ainda: o convite para o projeto e o aviso quando o relato anda, os primeiros a usar, são Planejado.

O servidor do projeto é o Brevo. O plano grátis manda 300 e-mails por dia e não pede cartão de crédito — sobra para um time pequeno. Ao contrário da fila e do armazenamento, não há nada dele no docker-compose.yml: é um servidor de fora, e a API fala com ele pela internet.

Smtp__Host=smtp-relay.brevo.com
Smtp__Port=587
Smtp__Security=StartTls
Smtp__Username=<o login SMTP>
Smtp__Password=<uma chave SMTP>
Smtp__FromAddress=<um remetente verificado>

No painel do Brevo, em SMTP e API → SMTP, ficam o login (algo como 9a1b2c001@smtp-brevo.com) e as chaves SMTP — uma chave gerada ali, e não a senha da conta. O remetente precisa estar verificado em Remetentes, domínios e IPs: o Brevo manda um código para o endereço confirmar que é seu. Sem domínio próprio, serve o seu e-mail de sempre — veja abaixo o que acontece com ele.

Cada envio é um e-mail de verdade

Não há caixa de mentira no desenvolvimento: o que a API manda chega na caixa de alguém e conta no limite do dia. Teste mandando para o seu próprio endereço. E a chave SMTP é segredo, como o resto do .env.local: peça a quem já roda o projeto, por canal privado.

Por que dois sublinhados

A configuração do e-mail é uma seção, Smtp, lida inteira para um objeto de opções (SmtpOptions). Numa variável de ambiente, o separador de seção do .NET é o __: Smtp__Host é a chave Smtp:Host. Os valores continuam no .env.local, como toda a configuração da API, e a seção é lida só das variáveis de ambiente: uma seção Smtp no appsettings.json não vale, porque senha de SMTP em arquivo versionado é senha vazada.

O remetente, e por que ele pode chegar trocado

Gmail, Yahoo e Microsoft só aceitam bem e-mail cujo remetente é autenticado: o domínio do endereço declara, no DNS, quem pode mandar em nome dele. Um @gmail.com mandado pelo servidor do Brevo não passa nisso — o domínio é do Google, e só o Google manda por ele.

Por isso, sem domínio próprio verificado no Brevo, ele troca o domínio do remetente na hora de mandar: o endereço verificado — o seu e-mail de sempre, por exemplo — sai como algo parecido com seu-nome@5000001.brevosend.com. O e-mail chega, com o remetente trocado. Verificar um domínio do produto, com os registros DKIM e DMARC que o Brevo mostra, é o que deixa o remetente com o nome dele: Adiado, para quando houver domínio.

As chaves da seção

ChavePara quê
Smtp__HostO servidor. Uma das quatro essenciais, com o remetente, o usuário e a senha: sem nenhuma delas, o e-mail fica indisponível.
Smtp__PortA porta. Padrão 587.
Smtp__SecurityStartTls (padrão, a porta 587), SslOnConnect (a porta 465) ou None (só um servidor na própria máquina ou numa rede fechada, sem senha).
Smtp__Username / Smtp__PasswordQuando o servidor exige. Os dois, ou nenhum.
Smtp__FromAddressO remetente. Obrigatório com o servidor configurado.
Smtp__FromNameO nome ao lado do remetente. Opcional.
Smtp__TimeoutSecondsQuanto esperar o servidor. Padrão 30, de 1 a 300.
Configurado pela metade, a API não sobe

Não configurar é uma decisão; configurar o servidor e esquecer o remetente é um engano, que só apareceria no primeiro e-mail que não saiu. Com qualquer uma das quatro essenciais preenchida, a subida confere tudo de uma vez e diz tudo o que está errado: servidor sem remetente, remetente que não é endereço, usuário sem senha, porta fora de 1 a 65535, porta ou espera escritas como texto, espera fora de 1 a 300 segundos, Security escrito errado. Linha em branco vale o padrão — Smtp__Port= é a porta 587.

E recusa usuário e senha com Security=None: a senha atravessaria a rede em texto aberto. Servidor que pede senha oferece TLS, então quem cai nisso errou o Security.

StartTls é obrigatório, e não "quando der"

Com StartTls — o padrão —, servidor que não oferece TLS é recusado, e nada sai. Conexão aberta só com Security=None, escrito de propósito. A alternativa — seguir aberto quando o servidor não oferece — é exatamente o que um intermediário na rede provoca para ler a senha.

O que o envio garante

  • Um destinatário por mensagem, com domínio. Lista separada por vírgula ou ponto e vírgula, quebra de linha no endereço e endereço sem @domínio são recusados antes de conectar.
  • O assunto é uma linha. Quebra de linha vira espaço: ninguém acrescenta cabeçalho — uma cópia oculta, por exemplo — escrevendo no assunto.
  • Texto sempre, HTML se houver. Todo leitor de e-mail mostra texto, e filtro de spam desconfia de mensagem só com HTML. O HTML vai como foi montado: quem monta escapa o que veio de pessoa.
  • Declarado como automático (Auto-Submitted: auto-generated): resposta de férias não volta para um remetente que ninguém lê.
  • Um teto de espera. Servidor que aceita a conexão e não responde não prende o envio para sempre.
  • O endereço de quem recebe não vai para o log — só o identificador da mensagem, que basta para achá-la no servidor.
Não é para mandar de dentro da requisição

Mandar e-mail na hora faria quem clicou esperar um servidor de fora, e uma falha no envio desfaria o que a pessoa fez — o convite foi criado, só o e-mail é que não saiu. O envio sai pela fila, depois de gravado, e com nova tentativa: Planejado, junto com o primeiro uso.

Com a API dentro do docker compose, nada muda: o .env.local é montado no container, e o servidor é o mesmo endereço de fora.

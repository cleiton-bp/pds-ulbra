O e-mail

SMTP pelo Brevo, enviado pela fila e nunca dentro da requisição.

Em resumo
  • Opcional: sem a seção Smtp, a API sobe e o envio fica indisponível.
  • Hoje sai o convite para o time; o aviso quando o relato anda é Planejado.
  • Configurado pela metade, a API não sobe e diz tudo o que falta.

Configurando o Brevo

Todo provedor fala SMTP, então trocar é só configuração. O plano grátis do Brevo manda 300 e-mails por dia, sem cartão. Ele é de fora, por isso não há nada dele no docker-compose.yml.

Smtp__Host=smtp-relay.brevo.com
Smtp__Port=587
Smtp__Security=StartTls
Smtp__Username=<o login SMTP>
Smtp__Password=<uma chave SMTP>
Smtp__FromAddress=<um remetente verificado>
  • Login e chave: em SMTP e API → SMTP. O login parece 9a1b2c001@smtp-brevo.com, e a chave é gerada ali (não é a senha da conta).
  • Remetente: verificado em Remetentes, domínios e IPs. Sem domínio próprio, serve o seu e-mail de sempre.
Cada envio é um e-mail de verdade

Tudo chega numa caixa real e conta no limite do dia: teste com o seu endereço. A chave SMTP é segredo, peça por canal privado.

Por que dois sublinhados

A seção Smtp é lida para SmtpOptions, e o __ é o separador de seção do .NET: Smtp__Host é a chave Smtp:Host. Ela vem só das variáveis de ambiente; no appsettings.json não vale, porque senha em arquivo versionado é senha vazada.

O remetente pode chegar trocado

Gmail, Yahoo e Microsoft pedem remetente autenticado pelo DNS do domínio, e um @gmail.com mandado pelo Brevo não passa. Sem domínio próprio verificado, o Brevo troca o domínio: sai algo como seu-nome@5000001.brevosend.com, e o e-mail chega igual. Verificar um domínio do produto, com DKIM e DMARC, está Adiado.

As chaves da seção

ChavePara quê
Smtp__HostO servidor. Uma das quatro essenciais, com o remetente, o usuário e a senha: sem nenhuma delas, o e-mail fica indisponível.
Smtp__PortA porta. Padrão 587.
Smtp__SecurityStartTls (padrão, a porta 587), SslOnConnect (a porta 465) ou None (só um servidor na própria máquina ou numa rede fechada, sem senha).
Smtp__Username / Smtp__PasswordQuando o servidor exige. Os dois, ou nenhum.
Smtp__FromAddressO remetente. Obrigatório com o servidor configurado.
Smtp__FromNameO nome ao lado do remetente. Opcional.
Smtp__TimeoutSecondsQuanto esperar o servidor. Padrão 30, de 1 a 300.
Configurado pela metade, a API não sobe

Com uma das essenciais preenchida, a subida diz tudo o que está errado: servidor sem remetente, remetente que não é endereço, usuário sem senha, porta fora de 1 a 65535, porta ou espera como texto, espera fora de 1 a 300 segundos, Security escrito errado. Linha em branco vale o padrão (Smtp__Port= é a 587). Usuário e senha com Security=None também são recusados.

StartTls é obrigatório, e não "quando der"

Servidor sem TLS é recusado, e conexão aberta só com Security=None. Seguir aberto é o que um intermediário na rede provoca para ler a senha.

O que o envio garante

  • Um destinatário, com domínio. Lista, quebra de linha e endereço sem @domínio são recusados antes de conectar.
  • Assunto em uma linha, para ninguém injetar cabeçalho.
  • Texto sempre, HTML se houver, com o que veio de pessoa escapado.
  • Declarado como automático (Auto-Submitted: auto-generated), para resposta de férias não voltar.
  • Um teto de espera contra servidor mudo.
  • Sem o endereço no log, só o identificador da mensagem.
Nunca de dentro da requisição

A rota grava e põe um pedido na fila, e o consumidor manda depois (ver A fila). Assim ninguém espera o servidor de fora, e uma falha não desfaz o convite. Sem fila, o convite fica indisponível.

O e-mail do convite

Assunto fixo, Convite para entrar num time (o nome do projeto, escrito por qualquer um, fica só no corpo), em texto e HTML: quem convidou, o projeto, o papel, a validade e o link (PANEL_URL mais /invite#t= e o link sorteado). O produto não é nomeado.

Não há nova tentativa automática. A tela de Membros mostra o selo "Não saiu" e oferece reenviar, e o log guarda só o tipo do erro. Com a API no docker compose, nada muda: o .env.local é montado no container.

A pessoa dá o título

A ferramenta pergunta, antes do texto: "Em poucas palavras, o que aconteceu?". A resposta vai junto do relato:

POST /public/reports
{ "Key": "pk_ABC123", "Type": "Bug",
  "Title": "O botão de pagar não responde",
  "Text": "Depois de escolher o cartão, o botão fica cinza e nada acontece.", ... }

A pergunta é opcional de fábrica. Na tela Ferramenta, o dono a torna obrigatória — e aí a API recusa o relato sem título (400) — ou a esconde, e o card mostra o começo do texto. O título que a pessoa escreveu fica em reporter_title e nunca muda.

O time reescreve, se quiser

PUT /projects/2be49b28-.../reports/9f3e.../title
{ "Title": "Pagamento recusado no celular" }

O card passa a mostrar o título do time, com o que a pessoa escreveu logo embaixo. Mandar vazio — ou o mesmo título dela — volta ao dela. Quem relatou continua vendo só o que escreveu, no acompanhamento e em "meus relatos": o título do time não sai do painel.

Quem, o quanto, o quê, até quando

PUT .../reports/9f3e.../assignee   { "UserPublicId": "b1000000-..." }
PUT .../reports/9f3e.../priority   { "PriorityPublicId": "7b2f..." }
POST /projects/2be49b28-.../labels { "Name": "pagamento" }
PUT .../reports/9f3e.../labels     { "LabelPublicIds": [ "c41a..." ] }
PUT .../reports/9f3e.../due-date   { "DueDate": "2026-10-16" }

Cada PUT devolve o card inteiro — a criação da etiqueta devolve a etiqueta —, e a linha do card na tela de Trabalho passa a mostrar a prioridade, as etiquetas, quem está com ele e o prazo. O card nasce sem nada disso: sem responsável e sem prioridade até alguém do time escolher.

A etiqueta nasce no card

No painel, escrever o nome de uma etiqueta que não existe oferece criá-la — qualquer pessoa do time cria, e o nome que já existe devolve a que existe, mesmo com duas pessoas criando o mesmo nome ao mesmo tempo. Enter põe a de nome igual, e nunca uma parecida. A tela Etiquetas, de quem administra, é para organizar depois: renomear, trocar a cor, apagar a que sobrou.

Vários cards de uma vez

Na lista da tela de Trabalho, cada linha tem uma caixa, e a do cabeçalho marca todas as que estão na tela. Com cards marcados, aparece a barra do lote: Mover para uma coluna, Responsável, Prioridade, Pôr etiqueta (as que o card já tem ficam), Tirar etiqueta e, com as sprints ligadas, Sprint — uma sprint aberta ou o backlog.

  • Card por card, pelas rotas de sempre — as mesmas regras e travas de mexer num card só. O card que já está como se pediu fica de fora; o recusado não desfaz os outros. No fim, a barra diz quantos mudaram, e um diálogo lista os que não mudaram, com o porquê.
  • Um de cada vez, na ordem da lista: a ordem em que chegam à sprint, ou ao topo da coluna, é a de quem marcou.
  • A coluna que encerra pergunta uma vez: os relatos abertos da seleção encerram todos com o mesmo desfecho e o mesmo motivo, e cada pessoa que relatou lê o mesmo texto.
  • A subtarefa não vai sozinha para a sprint: ela vai com o pai, e fica na lista do que não mudou.
  • Trocar o filtro, a coluna, a vista ou o projeto desmarca tudo: ninguém muda em lote o que não está vendo.
Nada disto chega a quem relatou

O acompanhamento, a consulta por código pessoal e a lista pública montam a resposta campo a campo, e nenhum deles conhece responsável, prioridade, etiqueta, prazo ou o título do time. A lista pública também não mostra o título que a pessoa escreveu: lá continua só o texto liberado.

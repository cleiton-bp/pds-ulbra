Criar o card do time

Nem todo trabalho chega pela ferramenta. Na tela de Trabalho, "Novo card" cria um card do próprio time — título, descrição em Markdown e a coluna em que ele nasce. No quadro, "Criar", no pé de uma coluna, abre o mesmo formulário já com ela escolhida:

POST /projects/2be49b28-.../reports
Authorization: Bearer <AccessToken>

{ "Title": "Trocar o provedor de e-mail",
  "Description": "Hoje sai pelo **plano grátis**.\n\n- verificar o domínio",
  "StatePublicId": "e12fef6c-..." }
{
  "Success": true,
  "Message": "Card criado.",
  "Data": { "PublicId": "7a1c...", "Kind": "Team", "Number": 42,
            "Title": "Trocar o provedor de e-mail", "TrackingCode": null,
            "CreatedByName": "Ana", "StateName": "Análise", ... }
}

Ele ganha o próximo número do projeto — #42 — da mesma sequência dos relatos: o relato que chegar depois pela ferramenta leva o #43. É o número que o time fala no grupo e escreve no commit.

O card do time não tem lado de fora

Sem protocolo, sem link de acompanhamento, sem código pessoal, sem etapa pública e sem moderação — e o banco recusa a linha que tente ter. Nenhuma porta pública chega a ele.

Trabalhar nele

O card do time anda pelos mesmos estados do relato, com o mesmo PUT .../state e o mesmo evento. Duas diferenças: mover para a coluna que encerra não pede desfecho nem motivo — não há quem relatou para ler —, e a etapa pública nunca se mexe por ele.

O título e a descrição se editam inteiros:

PUT /projects/2be49b28-.../reports/7a1c...
{ "Title": "Trocar o provedor antes de sexta", "Description": "..." }

O texto de um relato não passa por aqui (409): é de quem relatou, e fica como ela escreveu. O comentário interno serve aos dois; o comentário para quem relatou, o pedido de informação e o encerramento são só do relato.

A descrição é Markdown, e o painel a desenha sem HTML

Negrito, itálico, código, listas, títulos, citação e links — a barra do editor escreve as marcas, e a aba "Visualizar" mostra exatamente o que o card vai mostrar. O texto vira elementos na tela, nunca HTML: um <script> escrito na descrição aparece como texto. Link só com http, https ou mailto, e imagem não carrega.

Arquivar

PUT /projects/2be49b28-.../reports/7a1c.../archive
{ "Archived": true }

O card sai da tela de Trabalho e da contagem das colunas, e passa a aparecer em "Arquivados" (GET .../reports?archived=true). Arquivado se lê e se comenta; mover e editar pedem desarquivar antes — { "Archived": false }.

Arquivar um relato

O caminho do relato é encerrar com desfecho. Arquivar relato existe só com a regra do ciclo ligada — "Deixar o time arquivar relato", na tela de Ciclo —, e arquivar o relato aberto encerra junto:

PUT /projects/2be49b28-.../reports/9f3e.../archive
{ "Archived": true, "Outcome": "WontDo",
  "Reason": "Esta mudança não vai entrar no produto. Obrigado por escrever." }

Quem relatou abre o link e lê o motivo, como em qualquer encerramento. Dali, pode finalizar — confirmando, com a nota — ou reabrir. Reabrir traz o relato de volta para a tela de Trabalho sozinho: no histórico, "Desarquivou" aparece sem o nome de ninguém do time, junto de "Quem relatou reabriu". O relato já encerrado arquiva sem pedir nada: o motivo já foi.

Arquivar nunca deixa quem relatou sem retorno

Tirar um relato da tela do time sem dizer nada à pessoa seria exatamente o silêncio que o produto existe para acabar. Por isso o relato aberto só sai da tela com um motivo — e se a pessoa escrever de novo, reabrindo ou respondendo a uma pergunta que ainda estava aberta, ele volta.

O card do time e o arquivar

O trabalho que não veio de fora: criar, editar e arquivar.

Em resumo
  • O card do time nasce já com responsável, prioridade e lugar, se você quiser.
  • Duas pessoas editando a mesma descrição não se apagam.
  • Arquivar um relato aberto encerra junto, com um motivo para quem relatou.

Criar o card do time

Na tela de Trabalho, Novo card (ou a tecla "c", fora de um campo). Tudo vai num pedido só:

POST /projects/2be49b28-.../reports
Authorization: Bearer <AccessToken>

{ "Title": "Trocar o provedor de e-mail",
  "Description": "Hoje sai pelo **plano grátis**.\n\n- verificar o domínio",
  "StatePublicId": "e12fef6c-...",
  "AssigneeUserPublicId": "b1000000-...",
  "PriorityPublicId": "7b2f..." }
{
  "Success": true,
  "Message": "Card criado.",
  "Data": { "PublicId": "7a1c...", "Kind": "Team", "Number": 42,
            "Title": "Trocar o provedor de e-mail", "TrackingCode": null,
            "CreatedByName": "Ana", "StateName": "A fazer", ... }
}
  1. Responsável e prioridade são opcionais. O responsável precisa estar no time (vira evento e aviso no sino dele); a prioridade, estar ativa.
  2. Enter no título cria. Ctrl+Enter (⌘+Enter no Mac) cria de qualquer campo.
  3. Com as sprints ligadas, Entra em escolhe backlog, sprint em andamento ou planejada (SprintPublicId). O "Novo card" do topo começa no backlog; o campo da coluna no quadro, na sprint em andamento.
  4. O aviso do fim diz onde o card foi parar, com Abrir: "#42 criado.", "#42 criado no backlog." ou que ele não aparece por causa dos filtros.

O card ganha o próximo número do projeto (#42), da mesma sequência dos relatos. É o número que o time fala no grupo e escreve no commit.

O card do time não tem lado de fora

Sem protocolo, link de acompanhamento, código pessoal, etapa pública ou moderação. O banco recusa a linha que tente ter.

Trabalhar nele

Ele anda pelas mesmas colunas, com o mesmo PUT .../state e o mesmo evento. Mas encerrar não pede desfecho nem motivo, e a etapa pública nunca se mexe.

Para editar, clique em Editar, no título ou na descrição. O texto se grava inteiro, com a versão de onde a edição partiu:

PUT /projects/2be49b28-.../reports/7a1c...
{ "Title": "Trocar o provedor antes de sexta", "Description": "...",
  "Base": { "Title": "Trocar o provedor de e-mail", "Description": "Hoje sai pelo ..." } }
  • Se o card já não tem o texto de Base, outra pessoa salvou no meio: a API responde 409 em vez de escrever por cima.
  • A tela avisa ("Bruno salvou uma nova versão enquanto você editava.") e oferece Usar a versão nova ou Manter a minha. Vale também quando a versão chega pelo tempo real.
  • Compara o texto, não a data: quem só trocou a prioridade não atrapalha. Sem Base, grava como sempre.
  • O texto de um relato não se edita (409): é de quem relatou.
A descrição em Markdown

Negrito, itálico, código, listas, títulos, citação e links, com a aba "Visualizar". O painel desenha o texto como elementos, nunca HTML: um <script> aparece como texto. Link só com http, https ou mailto, e imagem não carrega.

Arquivar

PUT /projects/2be49b28-.../reports/7a1c.../archive
{ "Archived": true }
  • O card sai do Trabalho e da contagem, e aparece em "Arquivados" (GET .../reports?archived=true).
  • Arquivado se lê e se comenta. Para mover ou editar, desarquive: { "Archived": false }.

Arquivar um relato

Só com "Deixar o time arquivar relato" ligado, na tela de Encerramento. Arquivar o relato aberto encerra junto:

PUT /projects/2be49b28-.../reports/9f3e.../archive
{ "Archived": true, "Outcome": "WontDo",
  "Reason": "Esta mudança não vai entrar no produto. Obrigado por escrever." }
  1. Quem relatou lê o motivo, como em qualquer encerramento.
  2. Pode finalizar (com a nota) ou reabrir. Reabrir traz o relato de volta ao Trabalho, com "Desarquivou" e "Quem relatou reabriu" no histórico.
  3. O relato já encerrado arquiva sem pedir nada.

Assim, o relato aberto nunca some sem um motivo. Se a pessoa escrever de novo, ele volta.

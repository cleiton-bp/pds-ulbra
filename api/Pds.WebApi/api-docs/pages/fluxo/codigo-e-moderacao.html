Código pessoal e moderação

Outros jeitos de voltar ao relato, e a fila antes de algo ficar público.

Em resumo
  • O código pessoal e a identidade do seu sistema listam os relatos da pessoa, só para ler.
  • Confirmar, reabrir, responder e anexar continuam pedindo o token do link.
  • Em projeto público, só aparece o relato que o time liberou na Moderação.

Quem relatou volta pelo código

No modo código pessoal, a confirmação entrega também um código que vale para todos os relatos da pessoa naquele projeto. Quem já tem manda junto do relato novo; quem não tem recebe um. Código desconhecido vira um código novo.

a pessoa digita o codigo no quadro, num navegador qualquer ↓ POST /public/reports/by-code { Key, Code } ↓ codigo em branco, desconhecido, ou projeto que nao usa o modo → lista vazia, e nao 404 ↓ devolve ate 50 relatos, sem o token de nenhum ↓ a pessoa escolhe um → POST /public/reports/by-code/open { Key, Code, TrackingCode } ↓ grava "visualizado" com by: reporter_code → a mesma visao publica do link, com as acoes desligadas ↓ POST /public/reports/by-code/attachments { Key, Code, TrackingCode } → os arquivos, so para ler
  • Sem token na lista: senão doze símbolos valeriam tanto quanto todos os links juntos.
  • Só leitura: tracking_code_can_act segue gravado e ignorado até as outras rotas aceitarem o código, o que é Adiado.
  • Visualização: ver a lista e ler os arquivos não gravam; abrir um relato grava com by: reporter_code.
  • Os arquivos: passam pela mesma porta de by-code/open, com links de minutos, Cache-Control: no-store e sem o nome original.

Quem relatou volta pela identidade do seu sistema

Aqui a pessoa não guarda código: o site do cliente diz quem ela é.

  1. O servidor do cliente assina um crachá. De fábrica é a assinatura simples, HMAC-SHA256 de id.expira com a chave secreta da identidade; quem preferir usa um JWT ES256 com sub, aud igual à chave pública e validade curta.
  2. Ele vai nos atributos do <script> do carregador (data-user-id, data-user-expires e data-user-signature, ou data-identity com o JWT), e o quadro o manda no corpo de POST /public/reports.
  3. No primeiro relato nasce a linha em reporter_codes, com o hash do sub. A confirmação diz se ficou ligado (Identified).
o site poe o cracha nos atributos do script; o carregador o le a cada abertura e o quadro o manda ↓ POST /public/reports/by-identity { Key, IdentityToken } ↓ cracha que nao confere, pessoa que nunca relatou aqui, ou projeto fora do modo → lista vazia, e nao 404 ↓ devolve ate 50 relatos, sem o token de nenhum: sem campo de codigo: a lista carrega sozinha ↓ a pessoa escolhe um → POST /public/reports/by-identity/open { Key, IdentityToken, TrackingCode } ↓ grava "visualizado" com by: inherited_identity → a mesma visao publica do link, com as acoes desligadas ↓ POST /public/reports/by-identity/attachments { Key, IdentityToken, TrackingCode } → os arquivos, so para ler

As três rotas espelham as do código. Qualquer falha dá lista vazia ou a mesma recusa única, para não revelar a configuração do cliente nem algo sobre outra pessoa. Abrir grava com by: inherited_identity, e a página de acompanhamento recebe o crachá no fragmento (#i=), lendo os arquivos de by-identity/attachments.

Sem crachá, de fábrica o relato entra só com protocolo. Com "exigir o crachá" ligado, o quadro pede login antes, e o envio sem crachá dá 401. O que a API confere está em Rotas públicas.

O time libera um relato para o público

Em projeto público, a ferramenta mostra só o que passou pela fila. Todo relato nasce pendente:

GET /projects/{id}/reports/moderation → 25 pendentes, do mais antigo para o mais novo, e o cursor ↓ cada linha traz o texto inteiro e o que a varredura achou, com a amostra mascarada ↓ PUT .../reports/{id}/moderation { Decision: Approved | Rejected, From: Pending } ↓ outra pessoa decidiu antes? → 409, e nada muda ↓ grava report_published ou report_moderation_rejected, com quem decidiu ↓ GET /public/reports/published?key=... → os liberados, sem protocolo, sem identificador e sem anexo
Liberar não publica sozinho

Precisa do projeto público e do relato liberado, então tornar o projeto público depois não publica o histórico. Recusar não apaga nem encerra, e não há volta para pendente.

A lista pública é só texto

Ela mostra o texto e o andamento, sem arquivos. Imagens e uma página por relato aprovado são Adiado.

A tela de Moderação

  • Caixa de entrada: lista compacta, relato inteiro ao lado, teclado (J/K andam, L libera, N não publica, X seleciona) e decisão em lote.
  • Ordem: 25 por vez, dos mais antigos, e a varredura não fura a fila.
  • Histórico: Liberados e Não publicáveis vêm do mais recente, para desfazer um engano rápido.
  • Tempo real: só reconta as abas e mostra "N novos: mostrar".

Em projeto privado, uma faixa avisa: "Este projeto é privado, então nada daqui vai a público e você pode decidir sem pressa." A fila só importa depois de abrir os relatos na tela Privacidade.

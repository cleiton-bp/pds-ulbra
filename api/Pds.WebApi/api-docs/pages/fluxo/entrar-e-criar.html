Entrar e criar o projeto

Do login com Google ao projeto pronto para receber relatos.

Em resumo
  • O primeiro login já cria a conta: não há tela de cadastro.
  • O projeto nasce com colunas, andamento público, tipos, prioridades e a chave pública.
  • Quem administra um projeto sem relato entra pela configuração; o resto, pelo Trabalho.

Entrar

O painel faz o Sign-In com o Google e manda o token recebido:

POST /auth/google
{ "IdToken": "<id_token do Google>" }
{
  "Success": true,
  "Data": {
    "AccessToken": "eyJhbGciOi...",
    "ExpiresAt": "2026-08-18T06:13:43Z",
    "User": {
      "PublicId": "aaaaaaaa-...",
      "Name": "Ana",
      "Account": { "PublicId": "11111111-...", "Name": "Conta de Ana" }
    }
  }
}
  • No primeiro acesso, a conta própria e o usuário nascem nesta chamada.
  • Quem pediu para apagar a conta e entra dentro das 24 horas desfaz o pedido, e a resposta traz DeletionCancelled: true. Com o prazo vencido, entra como quem chega pela primeira vez.
  • O Account é sempre a conta própria. Projetos de outras contas vêm na lista de projetos, cada um com a sua.

Criar o projeto

POST /projects
Authorization: Bearer <AccessToken>

{ "Name": "Loja Online", "Template": "SimpleBoard" }

O painel pede o nome e como o time trabalha, entre quatro modelos, com o Quadro simples já marcado. Template é opcional, e sem ele vale SimpleBoard. A resposta traz o projeto e a chave pública:

{
  "Success": true,
  "Message": "Projeto criado.",
  "Data": {
    "Project":   { "PublicId": "2be49b28-...", "Name": "Loja Online", "Status": "Active",
                   "Account": { "PublicId": "11111111-...", "Name": "Conta de Ana" },
                   "Role": "Administrator", "IsAccountOwner": true,
                   "LastReportReceivedAt": null, "LastActivityAt": null },
    "PublicKey": { "Type": "Public", "Value": "pk_EXEMPLO1aBcDeFgHiJkLmNoP" }
  }
}

Quem cria é dono: por isso vêm Role: "Administrator" e IsAccountOwner: true. O painel abre o projeto em Configurar o projeto, com os cinco primeiros passos. No primeiro projeto da conta, antes vêm as boas-vindas, com o caminho até o primeiro relato.

Tudo nasce numa gravação só (ou entra tudo, ou nada):

  • a chave pública, que vai no script do site;
  • as colunas do modelo, em ordem, e a última encerra o relato;
  • o andamento público já ligado às colunas, como versão 1 do mapa (a próxima gravação vira a 2);
  • os tipos de relato, cada um com a coluna em que entra;
  • as prioridades Baixa, Média, Alta e Urgente, em todo modelo.
ModeloO que traz
Quadro simples
SimpleBoard		A fazer → Recebido, Fazendo → Em desenvolvimento, Feito → Concluído, com a jornada de fábrica de cinco etapas. Tipos de fábrica: Defeito (o que tentou fazer, o que aconteceu e o que esperava), Melhoria e Dúvida (caixa livre). Todos entram em A fazer.
Suporte
Support		Novo → Recebido, Em atendimento → Em atendimento, Aguardando quem relatou → Esperando você, Resolvido → Resolvido (desfecho "foi feito"). Em atendimento aceita a volta da jornada, quando quem relatou responde. Tipos Problema (três perguntas), Dúvida e Pedido (caixa livre), todos em Novo.
Kanban
Kanban		Backlog → Recebido, A fazer → Em análise, Fazendo → Em desenvolvimento, Em revisão → Em teste pela equipe, Feito → Concluído. Tipos de fábrica, entrando no Backlog.
Scrum
Scrum		A fazer → Recebido, Fazendo → Em desenvolvimento, Em revisão → Em teste pela equipe, Feito → Concluído. Tipos de fábrica e sprints ligadas de duas semanas, com pontos: o relato espera no backlog (ver Backlog e sprints).
Por que o projeto nasce assim
  • Colunas ligadas: com uma coluna só, o quadro não anda, e sem o mapa quem relatou leria "Recebido" para sempre. Tudo se renomeia e religa depois; projetos antigos ficam como estavam.
  • Modelo só na criação: aplicar num projeto com cards exigiria decidir o destino de cada um. O projeto não guarda o modelo; ele fica só no evento project_created, sem o nome do projeto.
  • Só a chave pública: sem ela o site não manda relato. A secreta nasce sob pedido, na tela de Chaves (ver A chave secreta, arquivar).

Por onde se entra no projeto

  • Todos caem no Trabalho, menos quem administra um projeto que ainda não recebeu relato: esse entra em Configurar o projeto.
  • Quem decide é o primeiro relato vindo do sistema do cliente: o relato de teste também preenche LastReportReceivedAt, mas não abre o Trabalho. LastActivityAt é o "último movimento" da lista.
  • O seletor do topo mantém a tela ao trocar de projeto; sem permissão no outro, cai no Trabalho.
A lateral e as áreas da configuração

A lateral começa por Trabalho, Membros e Moderação. Embaixo, só para quem administra, Configurar o projeto leva a uma página com os primeiros passos, a busca por qualquer opção e cinco áreas:

  • O seu sistema: Instalação, O botão, Domínios.
  • O formulário: Tipos de relato, Textos e tema, Anexos.
  • Depois de enviar: Andamento público, Encerramento, Privacidade.
  • O quadro: Colunas, Prioridades, Etiquetas, Sprints.
  • O time: Membros, Projeto.

Os endereços antigos das telas continuam valendo.

Conferir as chaves

GET /projects/2be49b28-.../keys
{
  "Data": [
    { "Type": "Public", "Value": "pk_EXEMP...", "Prefix": "pk_EXEMPLO1", "IsActive": true }
  ],
  "Total": 1
}
  • O projeto novo tem só a pública. A secreta, depois de gerada, vem com Value: null: o banco não guarda o valor dela.
  • Ler as chaves é de administrador (o dono sempre é). Membro recebe 403.

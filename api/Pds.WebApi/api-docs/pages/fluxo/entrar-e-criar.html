Entrar

O painel faz o Sign-In com o Google e manda o token recebido:

POST /auth/google
{ "IdToken": "<id_token do Google>" }

Resposta:

{
  "Success": true,
  "Data": {
    "AccessToken": "eyJhbGciOi...",
    "ExpiresAt": "2026-08-18T06:13:43Z",
    "User": {
      "PublicId": "aaaaaaaa-...",
      "Name": "Ana",
      "Account": { "PublicId": "11111111-...", "Name": "Conta de Ana" }
    }
  }
}

Se for o primeiro acesso, a conta própria e o usuário nasceram nesta chamada. Não há tela de cadastro. O Account da resposta é sempre a conta própria — os projetos de outras contas em que a pessoa estiver vêm na lista de projetos, cada um com a sua.

Criar o projeto

POST /projects
Authorization: Bearer <AccessToken>

{ "Name": "Loja Online" }

A resposta traz o projeto e a chave pública:

{
  "Success": true,
  "Message": "Projeto criado.",
  "Data": {
    "Project":   { "PublicId": "2be49b28-...", "Name": "Loja Online", "Status": "Active",
                   "Account": { "PublicId": "11111111-...", "Name": "Conta de Ana" },
                   "Role": "Administrator", "IsAccountOwner": true,
                   "LastReportReceivedAt": null, "LastActivityAt": null },
    "PublicKey": { "Type": "Public", "Value": "pk_1R0KtQwzLCVyS4RKh-8CqcHy" }
  }
}

O projeto nasce pronto para trabalhar, numa gravação só — ou tudo entra, ou nada entra:

  • a chave pública, que vai no script do site;
  • as colunas A fazer, Fazendo e Feito, nessa ordem. Feito, a última, é a que encerra o relato, pela regra de fábrica do ciclo;
  • o andamento público de fábrica, já ligado às colunas: A fazer → Recebido, Fazendo → Em desenvolvimento, Feito → Concluído. É a versão 1 do mapa, como se alguém tivesse salvo a tela — a próxima gravação vira a versão 2;
  • as prioridades de fábrica: Baixa, Média, Alta e Urgente.
Por que três colunas, e já ligadas

Com uma coluna só, o quadro não anda: ela era a entrada e o fim ao mesmo tempo, e o time precisava achar a configuração antes de mover o primeiro card. E sem o mapa o relato andava por dentro enquanto quem relatou continuava lendo "Recebido", sem ninguém perceber. Tudo se renomeia, reordena e religa depois — o padrão é ponto de partida, e não regra. Os projetos que já existiam ficam como estavam.

Por que só a chave pública nasce junto

Sem a pública o site não manda relato, e obrigar a um segundo passo só cria a chance de esquecer. A secreta serve a uma integração que pouca gente tem: nascendo junto, ela aparecia uma única vez para quem ainda nem sabia se precisava dela. Ela nasce sob pedido, na tela de Chaves — ver A chave secreta, arquivar.

O projeto nasce na conta própria de quem cria, e quem cria é dono dele — por isso a resposta traz Role: "Administrator" e IsAccountOwner: true. O painel abre o projeto na Instalação, com os três passos para o site começar a mandar relatos.

Por onde se entra no projeto

Abrir um projeto pela lista leva ao Trabalho, para todos — é onde o time passa o dia. A exceção é quem administra um projeto cujo site ainda não mandou relato nenhum: aí a Instalação é a próxima coisa a fazer, e é por ela que se entra. Quem decide é LastReportReceivedAt, que a lista de projetos traz em cada um — o último relato que chegou pela ferramenta, nulo enquanto nada chegou; o card do time não conta. LastActivityAt, a última mudança em qualquer card, é o "último movimento" que a lista mostra.

O seletor do topo mantém a tela: quem está em Colunas num projeto e troca para outro cai em Colunas do outro. Se a pessoa não administra o outro projeto, a tela de configuração vira o Trabalho; com um card aberto, a lista do outro projeto.

A lateral do projeto começa pelo que se usa todo dia — Trabalho, Membros e Moderação — e embaixo, recolhível e só para quem administra, Configurar o projeto, em dois blocos: Colunas, Prioridades, Etiquetas e Sprints; e Instalação, Chaves, Botão no site, Andamento público, Ciclo, Quem relata, Anexos e Projeto. Os endereços das telas continuam os de antes.

Conferir as chaves

GET /projects/2be49b28-.../keys
{
  "Data": [
    { "Type": "Public", "Value": "pk_1R0Kt...", "Prefix": "pk_1R0KtQwz", "IsActive": true }
  ],
  "Total": 1
}

O projeto novo tem só a pública. Depois de gerada, a secreta aparece na lista com Value: null: não é a tela que esconde — o banco não tem o valor dela para devolver.

Ler as chaves é de administrador, e o dono sempre é. Quem é só membro recebe 403: as chaves são a credencial da integração, e o trabalho nos relatos não precisa delas.

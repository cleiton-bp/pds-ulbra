Entrar

O painel faz o Sign-In com o Google e manda o token recebido:

POST /auth/google
{ "IdToken": "<id_token do Google>" }

Resposta:

{
  "Success": true,
  "Data": {
    "AccessToken": "eyJhbGciOi...",
    "ExpiresAt": "2026-08-18T06:13:43Z",
    "User": {
      "PublicId": "aaaaaaaa-...",
      "Name": "Ana",
      "Account": { "PublicId": "11111111-...", "Name": "Conta de Ana" }
    }
  }
}

Se for o primeiro acesso, a conta própria e o usuário nasceram nesta chamada. Não há tela de cadastro. O Account da resposta é sempre a conta própria: os projetos de outras contas em que a pessoa estiver vêm na lista de projetos, cada um com a sua.

Criar o projeto

POST /projects
Authorization: Bearer <AccessToken>

{ "Name": "Loja Online", "Template": "SimpleBoard" }

O painel pede o nome e como o time trabalha: quatro modelos, cada um com as colunas escritas, e o Quadro simples já marcado; quem só digita o nome e confirma recebe o projeto de sempre. Template é opcional, e sem ele vale SimpleBoard.

A resposta traz o projeto e a chave pública:

{
  "Success": true,
  "Message": "Projeto criado.",
  "Data": {
    "Project":   { "PublicId": "2be49b28-...", "Name": "Loja Online", "Status": "Active",
                   "Account": { "PublicId": "11111111-...", "Name": "Conta de Ana" },
                   "Role": "Administrator", "IsAccountOwner": true,
                   "LastReportReceivedAt": null, "LastActivityAt": null },
    "PublicKey": { "Type": "Public", "Value": "pk_EXEMPLO1aBcDeFgHiJkLmNoP" }
  }
}

O projeto nasce pronto para trabalhar, numa gravação só, ou tudo entra, ou nada entra:

  • a chave pública, que vai no script do site;
  • as colunas do modelo, na ordem. A última é a que encerra o relato, pela regra de fábrica do ciclo;
  • o andamento público do modelo, já ligado às colunas. É a versão 1 do mapa, como se alguém tivesse salvo a tela: a próxima gravação vira a versão 2;
  • os tipos de relato do modelo, cada um com a coluna em que entra;
  • as prioridades de fábrica, em todo modelo: Baixa, Média, Alta e Urgente.
ModeloO que traz
Quadro simples
SimpleBoard		A fazer → Recebido, Fazendo → Em desenvolvimento, Feito → Concluído, com a jornada de fábrica de cinco etapas. Os tipos de fábrica: Defeito, que pergunta o que a pessoa tentou fazer, o que aconteceu e o que esperava; Melhoria e Dúvida, cada um com a caixa livre e a pergunta certa dentro. Nenhum escolhe coluna: o relato entra em A fazer, a primeira ativa.
Suporte
Support		Novo → Recebido, Em atendimento → Em atendimento, Aguardando quem relatou → Esperando você, Resolvido → Resolvido. A jornada é de atendimento: Em atendimento aceita que a jornada volte para ela (o card volta da espera quando quem relatou responde, e sem a marca a volta seria uma regressão), Esperando você é a vez de quem relatou, e Resolvido é o fim, com o desfecho "foi feito". Tipos Problema (três perguntas), Dúvida e Pedido (caixa livre), todos entrando em Novo.
Kanban
Kanban		Backlog → Recebido, A fazer → Em análise, Fazendo → Em desenvolvimento, Em revisão → Em teste pela equipe, Feito → Concluído: a jornada de fábrica, uma etapa por coluna. Os tipos de fábrica, entrando no Backlog.
Scrum
Scrum		A fazer → Recebido, Fazendo → Em desenvolvimento, Em revisão → Em teste pela equipe, Feito → Concluído. Os tipos de fábrica. Sprints ligadas, de duas semanas, com pontos no card: o relato entra no backlog e espera o time puxá-lo para uma sprint (ver Backlog e sprints).
Por que as colunas já nascem ligadas

Com uma coluna só, o quadro não anda: ela era a entrada e o fim ao mesmo tempo, e o time precisava achar a configuração antes de mover o primeiro card. E sem o mapa o relato andava por dentro enquanto quem relatou continuava lendo "Recebido", sem ninguém perceber. Tudo se renomeia, reordena e religa depois: o modelo é ponto de partida, e não regra. Os projetos que já existiam ficam como estavam.

Por que o modelo só vale na criação

Aplicar um modelo a um projeto que já tem cards teria de decidir o que fazer com cada um deles, e com o mapa da época. Depois de criado, cada coisa se muda na própria tela, e o projeto não guarda de qual modelo veio: a escolha fica só no evento project_created, para a análise, sem o nome do projeto.

Por que só a chave pública nasce junto

Sem a pública o site não manda relato, e obrigar a um segundo passo só cria a chance de esquecer. A secreta serve a uma integração que pouca gente tem: nascendo junto, ela aparecia uma única vez para quem ainda nem sabia se precisava dela. Ela nasce sob pedido, na tela de Chaves (ver A chave secreta, arquivar).

O projeto nasce na conta própria de quem cria, e quem cria é dono dele: por isso a resposta traz Role: "Administrator" e IsAccountOwner: true. O painel abre o projeto na Instalação, com os três passos para o site começar a mandar relatos.

Por onde se entra no projeto

Abrir um projeto pela lista leva ao Trabalho, para todos: é onde o time passa o dia. A exceção é quem administra um projeto cujo site ainda não mandou relato nenhum: aí configurar é a próxima coisa a fazer, e se entra pela página central de Configurar o projeto, com os primeiros passos no topo. Quem decide é LastReportReceivedAt, que a lista de projetos traz em cada um: o último relato que chegou pela ferramenta, nulo enquanto nada chegou; o card do time não conta. LastActivityAt, a última mudança em qualquer card, é o "último movimento" que a lista mostra.

O seletor do topo mantém a tela: quem está em Colunas num projeto e troca para outro cai em Colunas do outro. Se a pessoa não administra o outro projeto, a tela de configuração vira o Trabalho; com um card aberto, a lista do outro projeto.

A lateral do projeto começa pelo que se usa todo dia (Trabalho, Membros e Moderação) e embaixo, só para quem administra, Configurar o projeto: um item só, que leva a uma página central com os primeiros passos (script colado, domínio autorizado, relato de teste, o botão com a cara do site, o time convidado), a busca por qualquer opção e as cinco áreas. Dentro da configuração, as áreas aparecem na lateral: O seu sistema (Instalação, O botão, Domínios), O formulário (Tipos de relato, Textos do formulário, Anexos), O acompanhamento (Andamento público, Ciclo, Quem relata), O quadro (Colunas, Prioridades, Etiquetas, Sprints) e O time (Membros, Projeto). Cada tela organiza os assuntos em grupos que dizem, fechados, o que está escolhido e o que já mudou do padrão. Os endereços das telas continuam os de antes, e o de um campo que mudou de tela leva à tela nova.

Conferir as chaves

GET /projects/2be49b28-.../keys
{
  "Data": [
    { "Type": "Public", "Value": "pk_EXEMP...", "Prefix": "pk_EXEMPLO1", "IsActive": true }
  ],
  "Total": 1
}

O projeto novo tem só a pública. Depois de gerada, a secreta aparece na lista com Value: null: não é a tela que esconde; o banco não tem o valor dela para devolver.

Ler as chaves é de administrador, e o dono sempre é. Quem é só membro recebe 403: as chaves são a credencial da integração, e o trabalho nos relatos não precisa delas.

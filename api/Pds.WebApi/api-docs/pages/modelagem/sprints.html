Sprints e backlog

Para o time que trabalha em ciclos curtos.

Em resumo
  • As sprints se ligam na tela Sprints (project_cycle_settings.sprints_enabled).
  • O card ganha a sprint, os pontos e o lugar no backlog.
  • Tudo é interno: quem relatou não vê sprint nem pontos.

As travas do banco

O estado fica na lista, o fim vem no começo ou depois, o número é único no projeto e há uma em andamento por projeto (índice único com state = 'active'). O serviço confere antes; o índice segura duas abas iniciando juntas.

O card nas sprints

  • reports.sprint_id: nula é o backlog. Com Restrict, apagar a sprint devolve os cards ao backlog antes. A subtarefa segue o pai.
  • reports.story_points: de 0 a 999, de meio em meio ponto (ck_reports_story_points). A subtarefa não leva.
  • reports.backlog_rank: o lugar nas listas, o menor em cima. O card novo entra no fim.

A sprint concluída

O que não terminou vai para o destino escolhido, e o que terminou fica nela como história. A lista traz só as sprints que andam; com closed=true, vêm também as concluídas.
